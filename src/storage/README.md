# Локальное хранилище Opora v2

Реализация: `src/core/storage.js`. Модуль подключается до инициализации состояния runtime.

## Ключи и схема

- Основной namespace: `localStorage["opora_v2_data_v1"]`.
- Legacy source: `localStorage["opora_v2"]`; сохраняется после копирующей миграции и не удаляется автоматически.
- Версия данных: `schemaVersion: 1`.
- Marker завершения: `opora_v2_data_v1_migration_complete`.
- Автоматические backup: `opora_v2_backup_<timestamp>`; сохраняются последние 10 обычных точек восстановления. Legacy-копии перед миграцией не удаляются этой ротацией.

## Гарантии

- При отсутствии целевого namespace приложение проверяет legacy-источник, создаёт backup и проверяет его чтением обратно до записи целевого состояния.
- Новая запись читается обратно и проверяется. Marker записывается после успешной сверки; исходный legacy-ключ остаётся доступен для восстановления.
- Повторный запуск миграции идемпотентен. Неизвестная будущая schemaVersion блокирует downgrade.
- Неизвестные поля и старые записи сохраняются; известные формы валидируются, повреждённый JSON не перезаписывается обычным save.
- Import выполняется через preview, затем отдельное подтверждение; перед заменой создаётся проверенная локальная backup-копия.
- Restore проверяет формат backup и исходный JSON до записи; write/read-back failure приводит к rollback-попытке и защищённому отказу.
- Хранилище и backup находятся в localStorage и не зашифрованы отдельным паролем. Это защита от случайной порчи/перезаписи, не криптографическое шифрование.

## Ограничения

Ручные проверки Android/iOS, полного цикла обновления PWA на целевых устройствах и реального Supabase backend остаются отдельными задачами. Не запускать миграцию на живом профиле для целей тестирования и не удалять legacy source без отдельного безопасного решения.
