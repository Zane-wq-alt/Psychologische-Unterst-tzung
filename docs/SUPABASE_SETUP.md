# Подключение независимой облачной синхронизации

Сейчас приложение локальное. Добавленный адаптер — рабочий транспортный слой, но не готовый аккаунтный сервис: владелец должен создать собственный проект Supabase, настроить Auth и передавать пользовательский access token. До этого облако не настроено, а данные остаются на устройстве.

## 1. Создать backend

1. Создать проект Supabase в регионе Frankfurt (Central EU), если он доступен в выбранном тарифе.
2. В SQL Editor выполнить миграцию `supabase/migrations/202611170001_opora_snapshots.sql`.
3. В Authentication включить выбранный способ входа и настроить разрешённые redirect URL.
4. Проверить RLS минимум двумя отдельными тестовыми аккаунтами: каждый аккаунт должен видеть только свою строку; попытка чтения/изменения чужого user_id должна возвращать пустой результат или отказ.
5. Проверить push при ожидаемой ревизии, конфликт при устаревшей ревизии и удаление облачной копии.

## 2. Подключить клиент

Создать адаптер:

```js
var transport = OporaSupabaseTransport.create({
  url: "https://YOUR_PROJECT.supabase.co",
  anonKey: "YOUR_PUBLISHABLE_OR_ANON_KEY",
  accessToken: function () {
    return authClient.auth.getSession().then(function (result) {
      return result.data.session && result.data.session.access_token;
    });
  }
});
var cloud = OporaCloudSync.create({ transport: transport });
```

`authClient` здесь — клиент Supabase Auth, созданный приложением-хозяином. В репозитории намеренно нет URL проекта, ключей или пользовательских токенов. Публичный anon/publishable key не заменяет авторизацию. Никогда не использовать service-role key в браузере.

Перед вызовом `cloud.enable(true)` интерфейс обязан отдельно показать, какие категории данных будут отправлены, где они будут храниться, как отключить синхронизацию и удалить облачную копию. Без отдельного согласия не вызывать enable/sync. Локальное сохранение должно продолжать работать при ошибках сети.

## 3. Протокол

- `pull()` читает только строку текущего пользователя благодаря RLS; отсутствие строки означает ревизию 0.
- `push()` вызывает SQL compare-and-swap RPC: новая ревизия создаётся только если ожидаемая ревизия совпала. Конфликт возвращает текущую ревизию и снимок, без молчаливой перезаписи.
- `deleteRemote()` удаляет только строку текущего пользователя.
- В таблице хранится JSONB-снимок. Он не шифруется приложением отдельно; HTTPS защищает передачу, а RLS — доступ на уровне БД. Это не end-to-end encryption.

## Ограничения перед включением

Этот репозиторий не может создать Supabase project, включить Auth или подтвердить RLS в чужой инфраструктуре. Пока эти шаги не выполнены и не проверены двумя аккаунтами, облако нельзя показывать как настроенное или включать в production. Не переносить реальные дневники в облако до отдельной оценки условий провайдера, срока хранения, удаления и доступа оператора.
