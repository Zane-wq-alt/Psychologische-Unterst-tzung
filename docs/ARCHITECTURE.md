# Архитектура «Опоры 2.0»

## Переходное состояние
Точка входа остаётся index.html. Старый runtime вынесен в src/legacy/app.js, стили — в src/ui/legacy.css. Runtime пока остаётся одним совместимым классическим скриптом. Это переходный слой, а не завершённая модульная декомпозиция.

## Целевая структура
    index.html / manifest.webmanifest / sw.js
    src/core/       — схема, миграции, валидация
    src/storage/    — local-first адаптер, backup/restore, будущий cloud adapter
    src/features/   — дневник, планирование, поддержка, общение, отчёты
    src/ui/         — тема, компоненты, навигация, доступность
    src/legacy/     — временный runtime до извлечения функций
    tests/          — проверки схемы, миграций и хранения
    docs/           — аудит, решения и инструкции

## Правила
1. core не зависит от DOM, UI, сети или хранилища.
2. storage отвечает за чтение/запись, экспорт и восстановление; без UI.
3. features используют API core/storage и не читают localStorage напрямую.
4. ui отображает состояние и передаёт действия функциям features.
5. Облачный адаптер — отдельный и необязательный; локальный режим работает без него.
6. Генеративного ИИ и интеграций с моделями в архитектуре нет.
7. legacy извлекается по одной функции после появления тестов.

## Порядок декомпозиции
1. Зафиксировать текущий формат данных и тесты чтения/записи.
2. Выделить схему и миграции в core.
3. Вынести local-first хранение и импорт/экспорт в storage.
4. Переносить функции по областям.
5. Перевести UI на явные модули и удалить legacy только после проверки эквивалентности.
6. Спроектировать независимое облако с opt-in отдельно; секреты не помещать в клиент.

## Инварианты
- Исходные данные не перезаписываются до резервного копирования.
- Неизвестные поля сохраняются при миграции.
- Повторная миграция безопасна.
- Сбой синхронизации не блокирует локальную работу.
- Отключение облака не удаляет локальную копию.

## Реализованное локальное хранилище (schema v1)

- Реализация: `src/core/storage.js`; подключается перед legacy runtime.
- Текущий ключ остаётся `localStorage["opora_v2"]`; версия записывается в поле `schemaVersion: 1`.
- Legacy-объект преобразуется в памяти; неизвестные поля и старые записи сохраняются.
- Перед записью результата миграции, импорта или сброса исходная строка сохраняется в отдельном ключе `opora_v2_backup_<timestamp>`. Если резервная копия не создаётся, операция отменяется.
- Повреждённый JSON, некорректные типы и будущая неизвестная версия не перезаписываются: приложение переходит в защищённый режим и предлагает скачать исходную строку или импортировать проверенную копию.
- При ошибке записи выполняется попытка вернуть исходную строку. Восстановление точки также сначала резервирует текущее содержимое.
- Проверки запускаются командой `node --test tests/*.test.cjs`; fixtures находятся в `tests/fixtures/`.
- Ограничение: это локальная защита от случайной потери данных, а не шифрование. Резервные копии в localStorage не защищены отдельным паролем.
