# Tests

Запуск локально: `node --test tests/*.test.cjs` (Node.js 20+).

## Fixtures

- `fixtures/legacy-full.json` — полный legacy-объект с записями профиля, чек-инов, эпизодов, архива чата и неизвестными полями.
- `fixtures/legacy-partial.json` — частично заполненное состояние.
- `fixtures/malformed.txt` — повреждённый JSON.

## Автоматические сценарии

1. Миграция legacy-данных и резервирование исходной строки.
2. Сохранение неизвестных полей и архива.
3. Частичные данные и идемпотентный повторный запуск.
4. Повреждённый JSON без перезаписи.
5. Некорректные типы коллекций без потери исходной строки.
6. Отклонение некорректного импорта.
7. Резервная копия перед успешным импортом.
8. Отмена операции при невозможности создать backup.
9. Rollback исходной строки при ошибке записи.
10. Восстановление backup и сохранение текущей версии перед откатом.
11. Защита от неизвестной будущей версии схемы.

GitHub Actions workflow: `.github/workflows/opora-storage-tests.yml`.

Браузерные e2e-проверки, офлайн-обновление PWA и проверка на живом профиле в этот набор не входят.


## Дополнительная защита

- Известные коллекции и вложенные массивы записей проверяются до миграции; неизвестные поля остаются нетронутыми.
- Значение `null` в известном массиве/объекте не подменяется значением по умолчанию: такая запись блокируется до ручного восстановления.
- Backup и результат записи проверяются чтением обратно; при несовпадении выполняется rollback.
- Перед восстановлением проверяется содержимое backup, а сохранённый raw JSON восстанавливается без переформатирования.
- Сохранение не перезаписывает повреждённое или неподдерживаемое существующее состояние.

## Защита от потери данных между вкладками и от тихих сбоев

- `external-change.test.cjs`: если другая вкладка изменила данные, `OporaStorage.save()` возвращает `external-change` и ничего не записывает; перезагрузка (`load()`) или осознанная замена (`replaceState()` с резервной копией чужой версии) снимает блокировку.
- `src/core/errors.js`: необработанные ошибки и отклонённые промисы показываются спокойным уведомлением и пишутся в локальный журнал (`opora_error_log_v1`, до 20 записей, без записей пользователя, без сети). Журнал можно скачать или очистить в разделе «Отчёт и данные».
- `browser-smoke.cjs`: сценарий двух вкладок и сценарий необработанной ошибки.

## Выборочное удаление

- `selective-delete.test.cjs`: разделы удаляются независимо, остальные данные, настройки, неизвестные поля и `cloudRevision` не меняются; результат проходит валидатор хранилища и записывается через `replaceState()` с точкой восстановления (`before-selective-delete`); `purgeLocalCopies()` удаляет точки восстановления и копию прежней версии, но никогда не единственный экземпляр данных.
- `browser-smoke.cjs`: сценарий в браузере (подтверждение, точка восстановления, окончательное удаление копий).
- Важно: точки восстановления и ключ `opora_v2` хранят удаляемые данные, пока их не удалить отдельным пунктом «окончательно удалить точки восстановления и копию прежней версии».

## Сквозное шифрование облака

- `e2e-cloud.test.cjs`: круг шифрования, отказ при неверной фразе/ключе/подмене/устаревших параметрах, смена фразы, транспорт с имитацией сервера (сервер не видит открытый текст), отказ от открытых копий в облаке, поток контроллера (ключ восстановления показывается один раз, облако включается только после подтверждения), шифрование по умолчанию в боевой сборке контроллера.
- `browser-smoke.cjs`: WebCrypto с боевыми параметрами (600 000 итераций) и панель облака в браузере.
- Не проверено: работа с реальным Supabase (проект не настроен).

## Слияние по записям

- `merge.test.cjs`: новое устройство принимает облако, объединение записей, распространение удалений только с базой, правка + новая запись, дубликаты, правила для листьев и конфликты, служебные поля, идемпотентность; случайная симуляция двух устройств (7 зёрен): сходимость и точное совпадение набора выживших записей.
- `browser-smoke.cjs`: сценарий синхронизации с изменением на «другом устройстве»: слияние, точка восстановления `before-cloud-merge`, отсутствие `cloudBase` в облаке и экспорте.

## Ресурсы и ограничение копий

- `assets.test.cjs`: стикеры — настоящие WebP-файлы, указаны путями и есть в офлайн-кэше; в основном скрипте нет встроенных изображений; precache без дублей и несуществующих файлов.
- `storage.test.cjs`: автоматические точки восстановления ограничены (по умолчанию 10), миграционные копии не удаляются.
